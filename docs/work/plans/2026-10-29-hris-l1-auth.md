# Plan HRIS L1 — Auth Terpusat

Tanggal: 2026-10-29 · Status: **draf; belum ada implementasi**
Spec: [Auth terpusat](../specs/2026-10-29-hris-l1-auth-design.md).
Dasar kode: origin/dev_hris. Setiap bagian memakai branch/worktree sendiri dan PR ke dev_hris,
lalu staging untuk uji owner. Aturan AGENTS.md terbaru mengalahkan alur lama pada PRD.

## Prasyarat

- [ ] Integrasikan aturan entry point terbaru ke dev_hris lewat PR tersendiri;
      jangan membawa semua fitur staging sebagai dependensi.
- [ ] Konfirmasi hasil uji L0 sebelum cutover L1; catatan saat planning masih menunggu owner.
- [ ] Tuntaskan keputusan terbuka pada spec §8 sebelum mengaktifkan sesi pusat.
- [ ] Publikasikan klaim implementasi per bagian; ambil kunci auth saat menambah migrasi,
      petshop hanya bila memang menambah migrasi aliran itu.
- [ ] Catat baseline dan daftar jalur login/logout/onboarding/reset/PIN/pilih cabang aktual.

## L1a — Kontrak, data, dan migrasi akun

Branch usulan feat/hris-l1a-accounts.
- [ ] Finalisasi tabel/kontrak Inggris pada spec, constraint dan batas app access.
- [ ] Buat migrasi aditif auth serta tes integrasi constraint/role database.
- [ ] Implementasikan preflight dan backfill idempoten: hash lama, status, PIN-only,
      benturan username/email dan tautan manual.
- [ ] Tetapkan konsistensi password dan provisioning selama fallback masih tersedia.
- [ ] Buktikan ulang backfill tidak menduplikasi dan kegagalan tidak meninggalkan muatan separuh.

Bukti: migrasi DB kosong + upgrade salinan lokal; preflight konflik menolak tanpa mutasi.
Jangan menjalankan backfill produksi dari laptop.

## L1b — Mesin sesi dan kredensial

Branch usulan feat/hris-l1b-sessions; bergantung L1a.
- [ ] Token acak yang disimpan sebagai hash, cookie lingkungan, validasi DB dan expiry.
- [ ] Password/login lockout lima kegagalan/lima menit; kewajiban ganti password awal.
- [ ] Akses per app, penguncian akun saat pengambilalihan, pengecualian OWNER.
- [ ] PIN hanya backoffice; HRIS rolling 30 hari berdasarkan aktivitas HRIS.
- [ ] Logout, reset, nonaktif, pencabutan tautan, audit dan login events.
- [ ] Tes waktu batas tepat, login serentak, pencabutan serta perlindungan origin/CSRF.

Bukti: matriks sesi spec §7 lulus di lapisan service dengan DB lokal terisolasi.

## L1c — Integrasi backoffice

Branch usulan feat/hris-l1c-backoffice; bergantung L1b.
- [ ] Pertahankan antarmuka verifyAccessToken; pemeriksaan sesi pusat dan akses app
      tanpa mengganti seluruh pemanggil.
- [ ] Adaptasi login password/PIN, onboarding, reset PIN, ganti password dan switch branch.
- [ ] Tambahkan bootstrap dari sesi pusat; cegah loop middleware dan pengambilalihan balik otomatis.
- [ ] Audit semua logout yang masih menghapus cookie saja; ganti dengan pencabutan server.
- [ ] Terapkan mode legacy/central dan batas token lama; buktikan jalan kembali.
- [ ] Uji dua akun pada PC bersama, OWNER multi-PC, GM satu akses dan hak/cabang kasir lama.

Bukti: tes regresi terarah + runtime backoffice lokal; kasir menggunakan kredensial lama.

## L1d — HRIS dan pintu provisioning

Branch usulan feat/hris-l1d-hris-access; bergantung L1c.
- [ ] Komponen login bersama dari package auth; halaman HRIS minimum dan logout.
- [ ] Tolak akun tanpa tautan; fixture terkontrol untuk uji akses sebelum data karyawan L2.
- [ ] Pintu internal backoffice dengan hak pelaku, secret, audit, idempotensi dan blok publik.
- [ ] Arahkan Pengguna backoffice ke layanan yang sama sampai layar L2 tersedia.
- [ ] Uji gagal di antara pembuatan user dan tautan; retry tanpa duplikasi.
- [ ] Sediakan kontrak reset/password dan riwayat untuk layar L2; jangan membuat data karyawan palsu.

Bukti: browser backoffice ↔ HRIS, PIN → password HRIS, logout lintas app,
dan provisioning berulang lulus di lokal.

## L1e — Staging dan kesiapan rilis

Branch usulan feat/hris-l1e-rollout; bergantung semua bagian sebelumnya.
- [ ] Env/domain/cookie berbeda per lingkungan; daftar origin eksplisit dan konfigurasi fallback.
- [ ] Runbook backup, preflight/backfill oleh migrator/prosedur deploy yang disetujui,
      cutover dan rollback; uji rollback menggunakan perubahan akun/kredensial nyata di lokal.
- [ ] Integrasikan dev_hris ke staging melalui PR dengan CI hijau.
- [ ] Jalankan matriks spec §7 pada dua PC/profil browser dan satu HP.
- [ ] Owner mencoba login POS lama, PIN, pilih cabang, sesi HRIS HP dan logout.
- [ ] Catat commit/tag tepat, bukti staging, keputusan cutover dan persetujuan rilis.
- [ ] Siapkan rilis terpilih dari main hanya sesudah gerbang rilis terpenuhi.

Bukti: **tayang staging — menunggu uji owner** sampai ada hasil owner eksplisit.
Integrasi development, staging, lolos uji owner dan produksi dicatat terpisah.

## Verifikasi tiap perubahan kode

Minimum pnpm typecheck root. Tes terarah untuk sesi, migrasi, race, hak akses dan
kompatibilitas login sesuai bagian; lint relevan. Jalankan pnpm migrations:check untuk
schema/migrasi dan pnpm changelog:check untuk fragment. Perubahan fitur/bugfix memakai
fragment Bahasa Indonesia pada path branch-nya. Jalankan verifikasi runtime Next.js
ketika perubahan app sudah tersedia. Suite luas tidak dijalankan lokal secara default;
CI tetap harus hijau sebelum merge.
