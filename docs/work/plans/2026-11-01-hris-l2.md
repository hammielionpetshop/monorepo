## Tujuan

Setelah L2, Owner/GM bisa membuat karyawan + akun + akses kasir dari HRIS, hak akses per jabatan
berlaku, pengajuan dasar berjalan, dan data karyawan lama termuat. Ini fondasi semua modul L3–L8.

## Prasyarat

- L1 aktif di produksi (cutover) **tidak** menjadi syarat membangun L2; L2 dibangun dan diuji di staging
  mode `central`. Tetapi L2 baru bisa dipakai nyata di produksi setelah cutover L1.
- Keputusan owner di bagian "Keputusan terbuka" di bawah, terutama daftar jabatan dan ekspor DB lama.
- Klaim path + kunci migrasi `hris` (dan `auth` bila ada migrasi tambahan) dipublikasikan per
  sub-langkah sebelum implementasi.

## Pemecahan sub-langkah

Urutan mengikuti ketergantungan data; bagian dengan tanda ‖ bisa paralel setelah pendahulunya selesai.

### L2a — Dasar tampilan HRIS (komponen + kerangka)
Bergantung: L1d. Tanpa migrasi.
- Sistem komponen dasar (tombol, isian, tabel/daftar, kartu, modal, toast, status kosong/galat),
  token desain, tema, tipografi — **mobile-first** (SIS-03).
- Kerangka aplikasi: header, navigasi yang dibangun dari daftar tindakan yang boleh (diisi L2b),
  halaman tanpa akses, pola daftar → rincian → langkah bertahap.
- Menggantikan tampilan sementara login/beranda L1d dengan komponen ini.
- Inilah titik polish UI yang dijanjikan: komponen dibuat sekali, modul sesudahnya memakai ulang.
- Verifikasi: uji owner di staging (HP + desktop). Tanpa tes UI otomatis.

### L2b — Hak akses, cabang, jabatan
Bergantung: L2a (navigasi) ‖ boleh mulai skema lebih dulu. **Kunci migrasi `hris`.**
- Tabel: cabang (ditautkan ke cabang kasir lewat view), departemen, jabatan, pengaturan jabatan,
  hak per jabatan (data), pengecualian per orang (KAR-L32), hak tambahan.
- Tindakan bernama di kode + fungsi tunggal `can(actor, tindakan, lingkup)`; lingkup
  diri/cabang/departemen/semua; batas keras KAR-72; GM setara Owner (KAR-67); jabatan berhak tinggi
  hanya diisi Owner/GM (KAR-74).
- Isi awal hak per jabatan dari `00-peta-modul.md` + rincian modul; layar Cabang & Jabatan,
  Pengaturan Jabatan, Hak Akses Jabatan (KAR-L30–L33).
- Tes: setiap tindakan dicoba sebagai tiap jabatan (KAR-63); batas keras tidak bisa dibuka.

### L2c — Karyawan (data induk)
Bergantung: L2b.
- Tabel karyawan, riwayat penempatan bertanggal (KAR-56), status kerja, nonaktif tanpa hapus (KAR-55),
  pekerja lepas, promosi training.
- Layar: Daftar Karyawan, Halaman orang, Catat perubahan penempatan, Nonaktifkan/aktifkan,
  izin tugas lapangan, Profil & Akun saya, ubah kontak/foto (KAR-L10–L14, L20–L24, L27–L29).
- **Tambah Karyawan** (pengganti pendaftaran, KAR-60): hanya Owner/GM; isian wajib KAR-01.
- Menonaktifkan karyawan memanggil `deactivateAccount` (kontrak L1) → akun nonaktif di semua app.

### L2d — Akun & Tautan
Bergantung: L2c. Memakai pintu internal L1d (pemanggil pertama).
- Layar Akun & Tautan: akun pusat beserta tautan (karyawan HRIS, pengguna kasir).
- Centang "punya akses kasir" → pilih role backoffice + cabang → panggil `/api/internal/hris/provision`
  (idempoten, berkunci layanan). Role dipilih eksplisit; jabatan hanya memberi saran bawaan.
- Tautkan pengguna backoffice lama ke karyawan secara manual; lepas tautan; reset password
  (`resetPassword`); Riwayat Masuk Semua Orang (KAR-L40, dari `auth.login_events`);
  Lupa password / kode dari GM menyesuaikan AUT-13.
- Semua perubahan tercatat di `auth.audit_events` + jejak HRIS.
- Kriteria: Owner membuat karyawan + akun + akses kasir → orang itu bisa login POS **dan** HRIS.

### L2e ‖ — Pengaturan bertanggal + jejak perubahan
Bergantung: L2b. **Kunci migrasi `hris`** (urut setelah L2b; satu pemegang).
- Tabel pengaturan bertanggal berlaku (WAJ-07), satu fungsi baca nilai-pada-tanggal, layar Pengaturan
  dan Ubah satu pengaturan (BER-L40/L41), siapa boleh mengubah/mengusulkan.
- Jejak perubahan (BER-L34): datanya dicatat sejak awal, layarnya menyusul.
- Tes: nilai lama untuk tanggal lama, nilai baru untuk tanggal baru; perubahan tidak mengubah hitungan
  yang sudah ditutup.

### L2f ‖ — Mesin Pengajuan, Pemberitahuan, Beranda dasar
Bergantung: L2b (hak), L2c (orang), L2e (pengaturan penyetuju).
- Satu jalur pengajuan: pengaju, untuk siapa, status, penyetuju, pemeriksa, alasan, lampiran,
  riwayat keputusan; KAR-72 (tak memutuskan pengajuan sendiri).
- Layar: Pengajuan Saya, pilih jenis, isian, rincian, Persetujuan, Putuskan, Jenis Pengajuan.
- Satu jenis contoh nyata: **Ubah data identitas (KAR-66)**.
- Pemberitahuan dalam aplikasi (daftar + belum dibaca) dan Beranda dengan kartu "perlu perhatian saya".
- Lampiran memakai upload terlindungi L0.

### L2g — Muat data awal + Pasangkan Groomer
Bergantung: L2c; ekspor DB HRIS lama dari owner.
- Skrip muat sekali pakai (aturan validasi sama dengan import kelak), tolak seluruh muatan bila ada
  satu baris salah dan laporkan baris + sebabnya; baris ditandai "bawaan sistem lama".
- Muat cabang, departemen, jabatan (SIS-26), karyawan (nama, kode/nomor, cabang, jabatan, status
  kerja, tanggal bergabung, HP, email, rekening). Gaji/kasbon/saldo di L9.
- Tautkan pengguna backoffice lama ke karyawan hasil muat.
- Layar Pasangkan Groomer & Pengantar (`petshop.groomers` → karyawan) lewat view baca.
- Dijalankan di staging dulu dengan salinan data; produksi adalah langkah terpisah dengan persetujuan owner.

## Urutan dan jalur kritis

```
L2a ─► L2b ─► L2c ─► L2d ─► L2g
          ├─► L2e ─┐
          └────────┴► L2f
```

Jalur kritis: L2a → L2b → L2c → L2d. L2e dan L2f bisa paralel dengan L2c/L2d bila kunci migrasi `hris`
diurutkan (satu pemegang pada satu waktu). Satu rilis ke produksi per kelompok bermakna, bukan per
sub-langkah (L2 baru berguna di produksi setelah cutover L1).

## Definisi selesai tiap sub-langkah

1. Tes mesin untuk logika non-UI (hak, pengaturan bertanggal, pengajuan, muat data) lulus; tes hak
   per jabatan untuk setiap pintu baru (WAJ-06). Tanpa tes UI otomatis (AGENTS.md).
2. `pnpm check:candidate` sekali pada kandidat akhir; `pnpm migrations:check` bila ada migrasi.
3. Uji owner di staging; catat kandidat, lingkungan, skenario, hasil.
4. WIP, papan klaim, dan fragmen changelog (bila menyentuh backoffice) diperbarui.

## Risiko

| Risiko | Penanganan |
|---|---|
| Hak akses salah → data gaji/karyawan terbuka | Tes per jabatan untuk tiap pintu; default tolak; batas keras KAR-72 di kode |
| Akun ganda/yatim antara HRIS dan backoffice | Hanya satu jalur pembuatan (pintu internal idempoten); tautan manual tercatat |
| Muat data awal merusak data | Skrip semua-atau-tidak, uji di staging dulu, ditandai "bawaan sistem lama" |
| Lingkup L2 besar | Pecah L2a–L2g; tiap bagian punya bukti selesai sendiri |
| Migrasi `hris` bentrok | Satu pemegang kunci `hris`; L2b → L2e berurutan |
